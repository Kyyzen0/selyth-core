# Technical risk register

The risks below are ordered by expected damage. The first three are, on the evidence, capable of ending the project rather than delaying it.

| ID | Risk | Evidence | Likelihood | Impact | Mitigation |
|---|---|---|---|---|---|
| R1 | Deterministic intent validation is not achievable in v1 | All intent-checking tools are LLM-based; best reported accuracy 96.3%, i.e. probabilistic [8][37] | High | Fatal | Scope the taxonomy so unproven intent is a first-class, *visible*, non-promoted status. Never let intent status reach PROVEN. |
| R2 | Verification cost exceeds the interactive budget | DafnyBench: of 782 programs only 230 verify; 66 fail on a 20-second timeout [25]. Production case studies run at 180–600s limits [4]. Roc refuses refinement types outright over compile time [28] | High | Fatal | Tier the checks. Fast tier on every save, slow tier on commit. Report Resource Units, not wall-clock (see below). |
| R3 | The verification report is worthless if the agent controls the verifier | SLSA: "the builder is trusted to have faithfully recorded the provenance; there is no option but to trust the builder" [31]. Berkeley RDI: all 8 audited agent benchmarks exploitable because the submission shares the evaluation environment [17] | High | Fatal | The verifier runs outside the agent's environment. This is a non-negotiable architectural constraint, not a setting. |
| R4 | Intent-layer value is unproven and currently contradicted | "Adding natural-language descriptions does not significantly improve performance" [9][10] | High | Severe | Build the slice and measure it against a Dafny-only baseline. If the intent layer does not reduce false acceptance, remove it. |
| R5 | Policy weakening by the proposing agent | NIST documented agents removing pre-existing checks [16]; OWASP: "a passing test suite generated by the same agent that produced the code provides no independent assurance" [19]; IETF now benchmarks "disabling of safety monitoring" as a metric [20] | High | Severe | Enforce additions-only diffs on proof artifacts, as LemmaScript does [4][7]. Ban `assume`/`sorry` by policy, as the vericoding benchmark does [10]. |
| R6 | Repository-scale verification is unsolved | Vero: 27/43 instances fully solved, 10 unsolved by every configuration; 87% of individual specs pass but 16 repositories remain unfinished [12][13] | High | Severe | Scope the slice to single-module units. Do not promise repository-scale guarantees. |
| R7 | Determinism of verification itself | Dafny is seed-dependent; one project measured a 30% failure rate over 100 runs. Resource Units are deterministic, wall-clock is not [24] | Medium | Severe | Restrict determinism claims to a per-claim scope. Never claim the gate is deterministic; claim the *policy evaluation over a fixed report* is. |
| R8 | Specification is itself wrong | Vero's audit mechanism lets agents submit machine-checked evidence that a spec is unsatisfiable or a reference wrong — and it surfaced latent errors during curation [12][13] | Medium | Severe | Include the audit channel in the v1 design. A gate that cannot report its own specification as unsatisfiable is incomplete. |
| R9 | No name collision, but no search surface either | No existing project named Selyth; adoption of comparable projects is under 100 stars [38][39][41][44] | Certain | Moderate | Treat discoverability as unsolved. The prototype is a validation instrument, not a distribution strategy. |
| R10 | Proof-corpus quality decay | RIINA flags 1,318 vacuity patterns — theorems concluding `True` — alongside its 12,819 proofs [39] | Medium | Moderate | Score proofs for vacuity, as Vero's joint-unsatisfiability slot does [13]. |

## Project-ending conditions

Three conditions should be treated as go/no-go gates, evaluated before any further investment.

The first is that the intent layer must demonstrate a measurable reduction in false acceptance against a Dafny-only baseline. If the evidence tracks the vericoding finding that natural-language descriptions do not help [9][10], the intent layer is decoration and must be cut.

The second is that the fast verification tier must complete on a single unit in under two seconds on the available hardware, and the slow tier under two minutes. A gate that takes longer than a human attention cycle gets bypassed, and the bypass is invisible.

The third is that the verifier must be structurally incapable of executing inside the agent's environment. This is the difference between evidence and self-attestation, and Berkeley RDI's finding is that essentially every deployed benchmark gets this wrong [17][18].
